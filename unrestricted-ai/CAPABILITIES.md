## Reliability and performance

Persistent cross-chat memory is available through `discover_host_tools(integration="memory")` and `call_host_tool`. The pinned official `@modelcontextprotocol/server-memory` 2026.8.31 server stores its graph in `integrations/profiles/memory/knowledge.jsonl`. All four model presets describe this capability. Creation, readback, on-disk persistence and cleanup passed directly through the authenticated bridge; model-driven use of this new integration has not yet been verified.

Source: https://github.com/modelcontextprotocol/servers/tree/main/src/memory

Dependency audit: the existing Desktop Commander tree reports four npm advisories through sharp/libvips and uuid/ExcelJS. No forced downgrade was applied. This remains an unresolved dependency limitation; the stack is not represented as flawless.

- `UnrestrictedAi-WSL-Anchor` keeps the dedicated WSL VM active; its persistence test passed.
- A WSL systemd timer reconciles only this project's Docker forwarding rules every 15 seconds. A deliberately removed rule was restored; the live regression also proved public DNS, external HTTPS, local service connectivity and sandbox isolation.
- Web-facing containers use two explicit IPv4 DNS upstreams, avoiding the unreachable synthetic IPv6 resolvers generated by WSL VirtioProxy on this host.
- `UnrestrictedAi-Health` runs under system Windows PowerShell with restart recovery and currently reports healthy services.
- Model-facing app open/focus and focused-editor typing tools remove guessed coordinates and verify fresh state.
- The ordinary launcher uses a content fingerprint for the two locally built images. The final unchanged launch skipped builds and completed in 13.69 seconds.
- Nine concurrent WebUI sandbox executions and the exact original sandbox execution check passed.
- The final post-repair stack verifier passed all 27 model, research, retrieval, execution and tool-transport checks in one run, including the 32K long-context `execute_python` continuation regression.

## Deliberate boundaries

The stack does not claim universal zero-error operation, every tool on the internet, exhaustive access to every source, or zero resource cost. Locked desktops, UAC, changed third-party interfaces, unavailable services, finite hardware and model behavior remain real constraints. Account-specific email, calendar, cloud-drive and similar APIs need their own supported endpoint, credentials and user authorization; existing signed-in browser tabs are available through profile 2.
